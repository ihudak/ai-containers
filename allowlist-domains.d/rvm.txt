# rvm bootstrap redirect target. https://get.rvm.io is a permanent redirect to
# https://bitbucket.org/mpapis/rvm/raw/master/binscripts/rvm-installer, and
# rvm-reconcile.sh fetches it with `curl -fsSL` (-L follows the redirect), so
# allowlisting get.rvm.io alone is not enough — the bootstrap dies on the hop.
# rvm's own `rvm get stable` (reconcile's install-failure retry) re-fetches
# through the same redirect and reads its Location: header to build the
# signature URL, so this host is needed for the retry path too.
bitbucket.org
# The installer resolves the "stable" tag from api.github.com first and falls
# back to api.bitbucket.org. Anonymous api.github.com is rate-limited per public
# IP — shared by every container behind one NAT — and a 403 with the fallback
# blocked means "Exhausted all sources trying to fetch version", not a retry.
api.bitbucket.org

# Runtime Ruby install (rvm now bootstraps + compiles Ruby inside the container).
# ftp.ruby-lang.org is rvm's ruby_url_fallback_1 (config/db), used when
# cache.ruby-lang.org fails to serve the source tarball.
cache.ruby-lang.org
ftp.ruby-lang.org
www.ruby-lang.org
keyserver.ubuntu.com

# rvm's PREBUILT-BINARY mirrors, named verbatim in its config/db:
#   rvm_remote_server_url=https://rvm-io.global.ssl.fastly.net/binaries
#   rvm_remote_server_url2=https://rubies.travis-ci.org
# Both were observed HARD-BLOCKED during a real Phase 3 bootstrap. Blocking them
# is not fatal — rvm falls back to compiling from source, which is why Ruby
# installs worked anyway — but it turns every first install into a multi-minute
# compile and leaves two permanent entries in blocked-domains.txt that read like
# a misconfiguration. Admitting them lets rvm take the binary path when one
# exists for the requested version.
#
# BOTH spellings of the Fastly host are listed on purpose. Fastly's legacy
# <service>.global.ssl.fastly.net form treats "-" and "_" interchangeably, and
# the two resolve to an identical A-record set; rvm's config/db requests the
# HYPHEN form while the blocked-capture DNS map recorded the UNDERSCORE one. The
# ipset would be correct with either (same IPs), but self-healing matches by
# NAME, so listing only one leaves the other reported as blocked forever.
rvm-io.global.ssl.fastly.net
rvm_io.global.ssl.fastly.net
rubies.travis-ci.org
